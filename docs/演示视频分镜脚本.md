## 二、② 功能演示：把「数据流」讲成含金量（0:25–3:40）

这一段不是随便点点，而是**用一次提问把 RAG 全链路走通**，并让每个环节在界面上都有可见证据。录制前把下面这张对照表放在手边，讲的时候按 1→9 的顺序指给观众看。

### 数据流 → 界面可见证据对照表（讲稿依据）

| # | 数据流环节 | 后端实现（可点开核对） | 界面上对应的可见证据 |
|---|---|---|---|
| 1 | 提问 | `ChatController.stream` | 输入框、发送后的用户气泡 |
| 2 | Query 改写 | `rag/QueryRewriter.java` | 「思考过程」面板里的**改写后 query** |
| 3 | 向量(pgvector) + 关键词(MySQL ngram) 混合召回 | `rag/HybridRetriever.java`、`rag/PgVectorStore.java`、`DocChunkMapper.fullTextSearch` | 面板里的**候选条数**、两路命中 |
| 4 | RRF 融合 | `HybridRetriever.rrfScore()`，公式 `1.0/(60+rank)`（源码 110–116 行） | 面板里**融合后的候选排序**（只依赖名次，无需对齐两路分数尺度） |
| 5 | 重排与阈值过滤 | `rag/RerankService.java` | 面板里的**保留条数 / 阈值**（候选 → 保留，低相关片段被丢弃） |
| 6 | Prompt 组装 | `rag/RagChain.java` + System Prompt（见 `docs/阶段2-架构与Prompt策略.md` §4.1/§4.2） | 面板里**组装后的参考资料 / Prompt** |

| 8 | [来源N] 溯源 | `groupedSources` / `safeUrl` 协议白名单 | 答案末尾 **[来源N]** + **来源卡片**，点击跳原文条款 |
| 9 | 会话落库 | `SessionController` / `t_chat_session` / `t_chat_message` | 左侧**会话列表**、刷新不丢、重命名／删除 |

### S2（0:25–0:50）登录 + 抛出首个问题

- **【画面/操作】** 普通用户演示账号已登录 → 停在问答页 → 输入框键入「国家奖学金怎么申请？」→ 回车发送，先不展开面板。
- **【口播台词】**「我用一个普通学生账号登录。今天不讲『点一下出个答案』，我想把一次提问背后完整的数据流走给大家看：从 Query 改写，到向量和关键词两路混合召回，RRF 融合，重排和阈值过滤，再到 Prompt 组装、DeepSeek 流式生成、来源溯源，最后会话落库。先问一个真实问题——国家奖学金怎么申请？」
- **【字幕要点】** 提问 → Query 改写 → 混合召回 → RRF → 重排/阈值 → Prompt 组装 → SSE 流式生成 → [来源N] → 会话落库
- **【录制提示】** 账号提前登录好（见第五节准备清单）；密码框不要出镜；发送后停 1 秒让「思考中」状态出现。

### S3（0:50–1:20）思考过程①：改写 → 混合召回 → RRF

- **【画面/操作】** 点击展开「思考过程 / 检索过程」折叠面板，逐行指读：改写后 query → 候选条数 → 融合排序；必要时切一次 IDE 露出 `HybridRetriever.java` 第 110–116 行的 `rrfScore`，再切回界面。
- **【口播台词】**「先看『思考过程』面板，这是普通大模型没有的东西。第一，系统把我的问题做了 Query 改写，变成一个更适合检索的完整问句。第二，两路同时召回：一路是 pgvector 的向量检索抓语义相近，一路是 MySQL 全文 ngram 抓精确措辞，比如条款号——面板上这个『候选条数』就是两路召回的总和。第三，用 RRF 把两路的名次融合，公式是 1/(60+rank)，只依赖名次，不需要把两路分数硬对齐；任一路失败还会 try-catch 降级，不影响主流程。」
- **【字幕要点】** Query 改写｜pgvector + MySQL ngram 两路召回｜候选条数｜RRF `1/(60+rank)`｜失败兜底
- **【录制提示】** 面板逐行展开节奏放慢；`HybridRetriever.java` 只露 `rrfScore` 那几行，避免长代码刷屏；字体已放大到可辨。

### S4（1:20–1:50）思考过程②：重排与阈值过滤 → Prompt 组装

- **【画面/操作】** 继续指读面板下半：候选条数 → 保留条数 → 阈值 → 组装后的参考资料。
- **【口播台词】**「召回多不等于准。接下来重排模型对候选精排，再用相关性阈值过滤，低相关片段直接丢掉——所以面板上『候选条数』会明显大于『保留条数』，这个差值就是精度控制。留下来的片段和问题一起被组装成最终 Prompt，System Prompt 里明确写了『只依据参考资料作答，资料不足就明说，不许编造』。到这里，喂给大模型的上下文已经是干净、可追溯的学校真实条款。」
- **【字幕要点】** 重排精排｜阈值过滤｜候选 → 保留｜反幻觉 System Prompt｜参考资料
- **【录制提示】** 候选数与保留数务必同框；可引用 `docs/阶段2-架构与Prompt策略.md` §4.1 的 System Prompt 原文作花字。

### S5（1:50–2:20）DeepSeek SSE 流式生成

- **【画面/操作】** 收起面板，镜头对准答案区，完整看一次打字机输出；生成结束后停留 2 秒，展示「转圈/加载态自动消失」。
- **【口播台词】**「现在才是调用 DeepSeek，通过 SSE 服务端推送，前端一边收一边逐字渲染，也就是打字机效果。注意两点：一是边生成边出字，不用等整段；二是生成完加载态自己会停——这一点我们后面修 Bug 的环节还会专门复现。答案末尾每个结论都带着 [来源N]。」
- **【字幕要点】** DeepSeek deepseek-chat｜SSE 流式｜逐字渲染｜自动停止｜[来源N]
- **【录制提示】** 不要切窗口、不要快进；若网络抖动，用预录的一段流式片段兜底（见第六节翻车点）。

### S6（2:20–2:50）[来源N] 溯源：来源卡片 → 原文条款

- **【画面/操作】** 鼠标悬停 [来源1] → 点击 → 弹出来源卡片（文件名、条款号、官网链接）→ 点开原文条款。
- **【口播台词】**「[来源N] 不是装饰。点开就是一张来源卡片：命中的具体文件、条款号、官网链接都在。这就是和普通大模型最大的区别——它只依据学校真实资料回答，每个结论都能查到出处，不瞎编。」
- **【字幕要点】** [来源N] 可点击｜来源卡片｜文件名 / 条款号 / 官网链接｜答案可溯源
- **【录制提示】** 编号上停顿 1 秒再点；来源卡片弹窗出现后停 2 秒让评委看清字段。

### S7（2:50–3:15）多轮追问 + Query 改写证据

- **【画面/操作】** 追问「那成绩要排前多少名？」→ 答案出现 → 再次展开思考面板，指读「改写后 query」已把「国家奖学金」补回。
- **【口播台词】**「我再追问一句，注意我没有重复『国家奖学金』三个字。系统结合上文把这句省略问句改写成了一个完整的检索问题——展开面板能看到改写后的 query 里自动补回了主体。这就是多轮对话的 Query 改写，不是把历史消息简单堆给大模型。」
- **【字幕要点】** 多轮上下文｜指代/省略消解｜改写后 query 自动补回主体
- **【录制提示】** 追问前不要新建会话，必须在同一会话里；展开面板时把「改写后 query」高亮。

### S8（3:15–3:40）会话落库 + 会话持久化 + 个人中心

- **【画面/操作】** 左侧会话列表 → 重命名 → 刷新浏览器 → 会话与消息仍在 → 一句话带过个人中心。
- **【口播台词】**「最后一步是会话落库。左侧这些历史会话都存在数据库里，我刷新一下——不丢，重命名、删除也都生效。整个系统是两级权限：普通用户用自己的会话，管理员才进得了后台；会话读写和流式问答都会校验归属，越权访问返回 403。个人中心还能改资料、换头像、改密码。」
- **【字幕要点】** 会话落库｜刷新不丢｜重命名/删除｜两级权限｜归属校验 403
- **【录制提示】** 刷新前后同框对比最有说服力；演示账号的会话别清空；不要真的删除会话。

## 三、③ 管理后台：闭环证据 + 参数热更新（3:40–5:00）

### S9（3:40–4:20）语料上传 → 切片预览 → 向量化 → 再提问命中新语料（闭环证据）⭐

- **【画面/操作】** 切到管理员账号 → 语料管理页 → 上传一份**尚未入库**的公开制度文件（md/txt/pdf/doc/docx 任一）→ 打开「切片预览」看到按条款切出的片段 → 点击「向量化」并显示切片数 → 回到问答页，提一个只有这份新文档能回答的问题 → 答案命中并带出新文档的 [来源N]。
- **【口播台词】**「光能问已有的语料不算闭环。我现在用管理员账号上传一份之前库里没有的制度文件，先看切片预览——法规类文档是按『条款』粒度切分的，所以溯源能直接命中具体条目。点向量化，切片和向量写进 pgvector/MySQL。然后我回到问答页，问一个只有这份新文件里才有答案的问题——它命中了，来源卡片指向的正是刚上传的文档。上传、切片、向量化、检索、命中，一条闭环当场走完，这就是知识库可持续更新的证据。」
- **【字幕要点】** 上传 → 切片预览（条款级）→ 向量化 → 再提问命中新语料｜闭环证据
- **【录制提示】** 提前准备一份不与现有 4 篇重复的文件（见第五节）；「向量化」后等切片数出现再切走；提问要设计成「旧语料答不出、新语料答得出」，对比最强；演示完不必删除，留作证据。

### S10（4:20–4:45）数据大屏 + 参数热更新（改阈值后答案变化）

- **【画面/操作】** 打开 ECharts 数据大屏（问答量、文档类型分布、热门问题）→ 进入参数配置页 → 记下「重排阈值」原值 → 调高阈值 → 回到问答页**问同一个问题** → 展开思考面板对比「保留条数」下降、回答收敛（来源减少，或按 System Prompt 返回「根据现有制度文件暂未找到明确依据，建议咨询相关部门」）→ 把阈值改回原值。

2. **准备语料文件**：从 `corpus/example/` 取一份**尚未入库**的公开制度文件（如 `学籍与教学管理-转专业条件.md`、`学生奖助-国家奖学金.md`、`学生管理-违纪处分.md`，或从 `docs/语料清单.md` 中另存一篇官网公开版），命名不与现有 4 篇已向量化文档重复；再设计好一个「旧语料答不出、新语料答得出」的提问。
3. **清空旧会话**：在演示账号里新建/清理出干净的会话起点，避免历史消息干扰镜头；**只清演示环境，不删真实数据**。
4. **服务就绪**：后端 8081、前端 5173、MySQL 8 / pgvector / Redis 容器都在跑；DeepSeek 等密钥已按 `README.md` 导出到当前 shell（注意 **Spring Boot 不读 `.env`**）；`hash` 与 `dashscope` 两种 provider 均为 1024 维，与 `sql/init_pgvector.sql` 的 `vector(1024)` 一致。
5. **预跑一遍**：先问一次「国家奖学金怎么申请？」确认能流式输出、能出 [来源N]、生成完自动停止；再跑一次 S9 的上传闭环，确认新语料可命中。
6. **录制环境**：OBS 场景/麦克风/提词器就绪，字体放大、勿扰打开、通知关闭，预截好 `git log --oneline` 与提交列表图；准备一段**预录流式片段**作网络兜底。
7. **参数原值记录**：抄下重排阈值、召回数等原值，S10 演示后改回。

### 常见翻车点与补救

| 翻车点 | 现场表现 | 补救 |
|---|---|---|
| 流式不输出 / 一直转圈 | 答案区空白或加载态不消失 | 查后端日志与 DeepSeek 密钥是否导出；切到备用的预录流式片段，口播改成「这是本地预录的同一链路」；该现象本身也可顺势呼应 S14 的「流式自动停止」Bug |
| 新上传语料问不到 | 答案没有指向新文档 | 确认点了「向量化」且切片数 > 0、维度为 1024、无空 catch 静默失败；备用：改用已入库的 4 篇之一完成闭环，口播说明「按对话记录整理」 |
| 阈值改太高触发「未找到依据」 | 回答变成拒答 | 正是反幻觉规则生效，口播顺势讲 System Prompt；随后把阈值改回原值再问一次 |
| 两个账号串号 / 401 | 后台进不去或跳登录 | 用独立浏览器配置文件重新登录；`request.ts` 的 401 登出是正常行为，别在镜头里慌乱重试 |
| 通知弹窗 / 隐私出镜 | 画面弹出消息、路径、密钥 | 勿扰 + 提前关客户端；已录到的片段后期打码或重录该镜头 |
| 字体太小、面板看不清 | 评委看不清候选条数/阈值 | 125%–150% 缩放 + OBS 局部放大画中画；关键数字做成后期花字 |
| API 超时 / 网络抖动 | 生成中断 | 预录片段兜底；无 DashScope 密钥时 rerank 会降级为纯混合检索（生成仍需 DeepSeek 密钥），口播如实说明降级边界 |
| 时间超 8 分钟 | 收尾仓促 | 优先压缩 S11（用户/公告管理）与 S17，**绝不压缩 ④ AI 协同段**（必须 ≥2 分钟） |
