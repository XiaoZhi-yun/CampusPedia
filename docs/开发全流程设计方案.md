# 学事通 CampusPedia · 开发全流程设计方案

> 校园学生事务智能问答（RAG）· 分阶段开发 + 边界测试 + 验收
> 版本：v1.0 ｜ 日期：2026-10-28

## 一、总体目标与时间线

| 里程碑 | 时间 | 内容 | 阶段 |
|---|---|---|---|
| **v0.1.0 预指导** | 10.31 | 核心链路能跑：导入→检索→问答→溯源→流式 | 阶段 0–3 |
| **v1.0.0 正式** | 11.18 | 全功能 + 复现指南 + 参赛材料 | 阶段 0–6 |

**开发原则**：每个阶段结束都达到"可运行、可验收、已提交"；阶段边界清晰，上一个阶段不稳定不进下一个阶段。

## 二、阶段总览

| 阶段 | 名称 | 一句话目标 | 完成标准（验收） |
|---|---|---|---|
| 0 | 项目骨架 | 环境就绪 | 后端编译✅ 前端构建✅（已完成）|
| 1 | 文档导入 + 切片 + 向量化 | 文件 → 切片 → 向量入库 | 上传文档后能查到切片，pgvector 不可用自动回退内存 |
| 2 | 检索 + 问答 + 溯源 | 提问 → 检索 → 生成带溯源答案 | 问"转专业条件"返回带 [来源N] 的答案且来源正确 |
| 3 | 流式 SSE + Chat 前端 | 浏览器逐字流式问答 | 浏览器打字提问，答案流式出现 |
| 4 | 思考可视化 + 引用高亮 | 展示检索过程 | 可展开看 Top-K 片段与相似度，[来源N] 可点击 |
| 5 | 管理端语料上传 | 上传/删除/更新语料 | 管理端改语料，知识库实时更新（补交能力）|
| 6 | 复现指南 + 参赛材料 | 10 分钟复现 + 材料 | 评委按 README 10 分钟跑通 |

## 三、全局测试策略

- **后端**：JUnit 5 + Mockito；对外部服务（DeepSeek/千问）用 Mock 隔离，避免测试依赖真实 Key。
- **前端**：先以手动验收为主（时间紧），核心纯逻辑（引用解析、流式拼装）抽函数用 Vitest 测。
- **三层测试**：
  1. 单元测试：切片器、检索、Prompt 组装等纯逻辑；
  2. 集成测试：上传→检索→问答端到端（Mock LLM/Embedding）；
  3. 手动验收：跑起来肉眼验证 UI/流式。
- **测试数据**：先用 3–5 篇高仿真示例语料（覆盖学籍/奖惩/奖助/就业/医保各一篇）做固定测试集；真实语料到位后复用同一套用例。

## 四、各阶段详细设计（边界 + 测试）

### 阶段 1 · 文档导入 + 切片 + 向量化

**范围边界**
- ✅ 做：文件上传接口、文本提取（先支持 .md/.txt，再补 .pdf/.docx）、条款级切片器、千问向量化、向量库（内存实现 + pgvector 可选）、文档列表/删除接口。
- ❌ 不做：检索、问答、前端 UI（本阶段用接口/命令行验证）。

**任务分解**
1. 语料目录初始化 + 示例语料 3–5 篇；
2. 文本提取（Markdown 先通，PDF/Word 用 PDFBox/POI）；
3. 切片器（按标题/条款边界切，300–500 字 + 50 重叠，保留"文件名+章节"元数据）；
4. 千问 Embedding 客户端（可配置 Key）；
5. 向量库抽象：`VectorStore` 接口，`MemoryVectorStore` + `PgVectorStore`；
6. `POST /api/documents`（上传→切片→向量化→入库）、`GET /api/documents`、`DELETE /api/documents/{id}`。

**测试**
- 单元·切片器：正常条款切分、长段落截断、重叠正确、空文档、纯标题无正文、超长单文档（>1万字）、中英文混排。
- 单元·文本提取：md/txt 正常、空文件、PDF 无文字（扫描件）、docx 解析。
- 单元·向量化：Mock DashScope 返回固定向量，校验维度一致、异常抛错。
- 集成·入库：上传→切片→入库，断言切片数与内容正确。
- **边界/异常**：空文件、超大文件（>10MB 拒绝或告警）、Key 缺失（启动时提示但不崩溃）、DashScope 超时重试、**pgvector 连不上自动回退内存且不报错**。

**验收**：上传一篇 Markdown 后内存库有正确切片；停掉 Docker 再上传，仍能走内存回退。

### 阶段 2 · 检索 + 问答 + 溯源

**范围边界**
- ✅ 做：检索服务（Top-K + 阈值）、Prompt 组装、DeepSeek 调用、溯源元数据映射、`POST /api/chat`（非流式 JSON 先跑通）。
- ❌ 不做：前端、流式渲染（阶段 3）、可视化（阶段 4）。

**任务分解**
1. 检索服务（余弦相似度，Top-K=6，阈值 0.5）；
2. Prompt 组装（System Prompt + 参考资料 + 问题）；
3. DeepSeek 客户端（可配置 Key）；
4. 溯源：chunk 元数据（文件名/条款/官网链接）→ 回答 [来源N] 映射；
5. `POST /api/chat` 返回 `{answer, sources[]}`。

**测试**
- 单元·检索：Top-K 数量、阈值过滤、空结果、按相似度排序、pgvector 与内存回退结果一致。
- 单元·Prompt 组装：模板填充、来源编号顺序、超长上下文截断（保留问题 + 头部来源）。
- 集成·端到端：Mock LLM 返回固定答案，断言 answer + sources 正确。
- **边界/异常**：空问题（400）、无相关片段（返回"未找到依据"）、参考资料超长、DeepSeek 超时/报错（降级提示）、Key 缺失、非校园问题（礼貌说明）。

**验收**：问"转专业要什么条件"，返回答案带 [来源1]，且来源指向《学籍管理规定》正确条款。

### 阶段 3 · 流式 SSE + Chat 前端

**范围边界**
- ✅ 做：SSE 流式接口、Chat UI（消息列表、输入框、流式逐字渲染）、Vite proxy 联调。
- ❌ 不做：引用高亮、思考可视化（阶段 4）、管理端（阶段 5）。

**任务分解**
1. 后端 `POST /api/chat/stream`（SSE：先发 sources，再流式 answer）；
2. 前端 Chat 组件（提问、历史消息、流式追加、loading 态）；
3. 错误态/空态 UI。

**测试**
- 集成·SSE：流式分片顺序、结束事件、断连处理。
- 前端·手动验收：逐字出现、多轮追问、错误提示友好。
- **边界/异常**：SSE 中途断开（前端提示重试）、空回答、超长回答、慢网络 loading 提示。

**验收**：浏览器打字提问，答案逐字流式出现，无卡死。

### 阶段 4 · 思考可视化 + 引用高亮

**范围边界**
- ✅ 做：检索过程面板（Top-K 片段 + 相似度分数 + 组装后 Prompt）、[来源N] 高亮 + 点击跳官网。
- ❌ 不做：管理端（阶段 5）。

**任务分解**
1. 后端检索结果附带元数据（片段、相似度）透传前端；
2. 前端"思考过程"折叠面板；
3. 引用高亮 + 来源链接。

**测试**
- 前端：高亮渲染、来源点击、面板开关、无来源时隐藏面板。
- **边界/异常**：无来源、来源链接失效（降级为纯文本）、相似度展示为 0。

**验收**：回答后可展开看到检索片段与相似度，答案 [来源N] 可点击跳官网。

### 阶段 5 · 管理端语料上传

**范围边界**
- ✅ 做：管理页（上传多格式、删除、重新向量化、文档状态列表）。
- ❌ 不做：登录/权限（竞赛 demo 不做鉴权，README 说明）。

**任务分解**
1. 管理页 UI（上传、列表、删除、刷新）；
2. 上传后自动重新切片+向量化；
3. 删除后同步移除向量。

**测试**
- 集成：上传新文档→可被检索；删除→不再被检索；更新同文档→新版本覆盖旧向量。
- **边界/异常**：重复上传同名（提示覆盖）、上传失败回滚、批量上传、文件格式不支持提示。

**验收**：管理端上传一篇新文档后，立刻能问答到其中内容（**补交/更新能力验证**）。

### 阶段 6 · 复现指南 + 参赛材料

**范围边界**
- ✅ 做：README「10 分钟复现指南」、docker-compose 一键、启动脚本、.env 模板、技术文档 PDF（≤30 页）、Prompt 链快照整理、演示视频脚本。
- ❌ 不做：新功能。

**测试/验收**
- 按 README 从零复现：clone → 配 Key → 一键起 → 上传语料 → 问答，全程 ≤10 分钟；
- 一键脚本在无 Docker / 无 pgvector 环境也能跑（内存回退验证）。

## 五、跨阶段异常清单（贯穿全程）

1. API Key 缺失/失效 → 启动与调用时友好提示，不崩溃；
2. 外部 API 超时/限流 → 重试 + 降级提示；
3. pgvector 不可用 → 自动回退内存；
4. 空输入/空语料 → 明确提示；
5. 超大文件/超长上下文 → 截断或拒绝，防内存溢出；
6. 并发请求 → 线程安全，向量库读写不冲突；
7. 死循环/性能 → 检索与生成设超时上限，防"性能死循环"扣分。

## 六、执行规则

- 每阶段：**开发 → 测试 → 验收 → commit + push**，验收不通过不进入下一阶段；
- 每阶段完成打 tag（阶段里程碑），10.31 打 `v0.1.0`，11.18 打 `v1.0.0`；
- 每个核心功能记录完整 Prompt 链（参赛材料）。

## 七、风险与应对

| 风险 | 应对 |
|---|---|
| 语料未到位 | 先示例语料跑通，真实语料到位无缝替换 |
| Key 未到位 | 代码外置环境变量 + Mock 测试，Key 到了填上即用 |
| GitHub 网络 | 加速器开着 push；本地 commit 永不失 |
| 时间紧 | 阶段 0–3 优先保 10.31；4–6 是加分项 |
