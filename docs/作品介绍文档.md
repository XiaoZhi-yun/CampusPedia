## 一、项目详情及使用方式

### 1.1 项目详情

**学事通（CampusPedia）** 是一款面向高校学生的校园事务智能问答系统。校园制度分散在教务处、学生处、就业处等多个官网，检索成本高；通用大模型又不掌握校内规章，容易凭空作答。学事通把这些**公开的真实制度文档**导入知识库，以「混合检索 + 重排序 + 大模型」为技术主线，为学生提供**流式问答、答案 [来源N] 溯源、检索过程可视化**的一站式咨询体验。

系统的核心准绳是：**只依据学校真实制度资料回答，资料不足时明确说明「暂未找到依据」，不臆造**；每条结论都标注 [来源N]，可点击回溯到命中的具体文件与条款，让答案「看得见来处」。

**语料现状**：已导入并向量化 **4 篇河南理工大学真实制度文档**（国家奖学金管理办法、学生体质健康标准、监考守则与考场规则、学生星级宿舍评比办法），共 **53 个切片**；语料库另备 **34 篇河南理工大学制度文件**可供批量导入。知识库按 **6 大类 +「其他」兜底共 7 个分类**组织（学籍与教学管理、学生管理、学生奖助、素质拓展、学生就业、医疗保障、其他），与官网公开制度体系一致。语料仅收录公开制度文件，不含个人隐私数据。

**权限模型**：系统采用**普通用户 / 管理员两级权限**，**无游客模式**，问答与管理功能均需登录后按角色访问。

**工程与参赛材料**：开发过程以细粒度提交推进，累计 **99 次 git 提交**（每个功能或修复一次提交、中文描述 + 英文前缀），全程可追溯；配套 20 页 Word 技术文档与演示视频，便于评委独立复现与核验。

### 1.2 学生侧使用流程

1. **注册登录**：以「学号 + 密码」注册并登录；密码以 BCrypt 加密存储，登录后签发 JWT，问答与会话记录持久化保存。
2. **提问**：在单层输入框用自然语言提问，例如「国家奖学金怎么申请？」「星级宿舍怎么评？」；系统结合多轮上下文做 Query 改写，把「那能评几次？」这类追问补全为完整检索问题。
3. **流式作答**：后端通过 SSE（Server-Sent Events）逐字推送，前端打字机式边生成边展示，生成过程中可随时**停止**。
4. **[来源N] 溯源**：答案在首次引用处标注 [来源N]，展开来源卡片可查看命中的文件名、条款与官网原文链接，点击跳转原文；检索过程面板同步展示改写 query、候选条数、保留条数与阈值。
5. **会话历史**：左侧栏列出历史会话，支持重命名、删除，刷新不丢失；会话读写与流式问答均校验归属，仅本人可见。
6. **个人中心**：修改姓名、专业、班级，更换头像、修改密码。

### 1.3 管理员侧使用流程

- **语料上传 / 向量化 / 切片预览**：上传 md / txt / pdf / doc / docx 制度文件，按 7 个分类归类，一键完成文本提取、按条款切分、向量化入库；支持切片预览、删除与重新向量化，删除时级联清理切片、向量与物理文件。
- **参数热更新**：在线调整切片大小、切片重叠、混合召回条数（topK）、最终保留条数、重排阈值、系统提示词、LLM 温度等 RAG 参数，无需重启即时生效。
- **数据大屏**：基于 ECharts 展示问答量趋势、文档类型分布、热门问题等运营指标。
- **用户与公告管理**：管理用户角色与资料、启停账号、删除用户并级联清理其数据；发布、置顶系统公告。

### 1.4 部署方式（简述）

完整「保姆级」复现步骤见仓库根目录 `README.md`，摘要如下：

1. **环境准备**：Docker Desktop、JDK 17、Node.js 18+；复制 `.env.example` 为 `.env`，填写数据库口令、`JWT_SECRET`（至少 32 字节，留空时后端启动即 fail-fast）、`DEEPSEEK_API_KEY` 等。`docker compose` 会自动读取 `.env`，但 **Spring Boot 不读 `.env`**，后端进程需另把变量导出到当前 shell（命令见 README）。
2. **三容器一键启动**：`docker compose up -d` 拉起 **MySQL 8（3307，元数据 + 全文检索）/ Redis 7（6379，预留，当前业务未启用缓存）/ pgvector（5432，向量持久化）**；再执行 `sql/init.sql`（9 张表）与 `sql/init_pgvector.sql`（`vector(1024)`）建表。
3. **启动后端**：`cd backend && ./mvnw spring-boot:run`，端口 8081。
4. **启动前端**：`cd client && npm ci && npm run dev`，端口 5173，浏览器访问 `http://localhost:5173`。

默认 `EMBEDDING_PROVIDER=hash`：免密钥、离线可跑，**hash 与 dashscope 两种 provider 均输出 1024 维**，与 `vector(1024)` 严格一致；切到千问需设置 `EMBEDDING_PROVIDER=dashscope` 并填 `DASHSCOPE_API_KEY`。**生成答案必须配置 DeepSeek Key**；**无 DashScope Key 时 rerank 自动降级为纯混合检索**，问答主流程不受影响。

## 二、项目亮点

1. **只依据真实制度回答 + 全链路可溯源**：系统提示词强约束「只依据参考资料作答，资料不足就明说」，答案在首次引用处标注 [来源N]，点击可回溯到具体文件条款与官网原文，从机制上抑制幻觉。
2. **混合检索 + RRF + 重排 + 阈值过滤**：pgvector 向量检索与 MySQL FULLTEXT（ngram）关键词检索双路召回，用 RRF（1/(60+rank)）融合排名，再经 qwen3.7-text-rerank 精排、相关性阈值过滤，兼顾召回率与精度；两路检索各自异常兜底、互不影响。
3. **按法规条款切分**：针对制度类文档按「条 / 章」边界智能切分并保留条款引用（clause_ref）元数据，使检索结果直接命中具体条目，溯源粒度精确到条款而非整篇文件。
4. **两级权限 + 实时鉴权 + 会话归属校验**：普通用户 / 管理员两级角色、无游客模式；JWT HS256 过滤器每次请求实时查库校验账号状态与角色，权限变更即时生效；会话读 / 改名 / 删除与流式问答均校验 owner，越权返回 403（IDOR 防护）。
5. **流式 SSE + 可停止**：SSE 先推送来源、再逐字推送答案；前端收到结束事件立即停止渲染，用户也可随时手动中断，配合统一的错误提示与重试，边缘场景（断连、空回答、SSE 换行）均有处理。
6. **安全加固**：密钥全部走环境变量、不入代码库；BCrypt 密码哈希、JWT 无状态鉴权、接口限流、上传文件名净化与落盘目录边界（防路径穿越）、source_url 协议白名单、全局异常响应脱敏，多重防线覆盖认证、授权与输入。
7. **健壮可降级**：embedding 提供免密钥 hash 与千问 dashscope 两种 provider 且维度统一 1024；无 DashScope Key 时 rerank 降级为纯混合检索；pgvector 不可用时向量层回退；生成必须 DeepSeek Key，缺失时给出明确提示而非静默失败。
8. **完整管理后台**：语料全生命周期管理（上传 / 切片预览 / 向量化 / 删除）、RAG 参数在线热更新、ECharts 数据大屏、用户与公告管理，配合学生侧会话历史与个人中心，开箱即用。

## 三、AI 测试技术落地使用情况概述

项目以「**自动化测试 + 检索质量评估 + Prompt 迭代测试 + 端到端分阶段验收**」构成测试体系，AI 生成代码与人工引导修正同步沉淀为回归用例，重点保障检索链路、权限边界与数据规范。

### 3.1 自动化测试（CI 自动执行）

- 后端 **JUnit 5 + Mockito 共 34 例**：对切片、RRF 融合、JWT、鉴权过滤器、会话归属、上传净化等纯逻辑与外部依赖做隔离测试；对 DeepSeek / 千问用 Mock 隔离，不依赖真实 Key。
- 前端 **Vitest 共 7 例**：覆盖 axios 请求拦截器的 token 注入、业务错误码、401 登出与 auth 端点例外。
- **CI 自动跑**：`.github/workflows/ci.yml` 在 push / PR 时自动执行后端 `./mvnw -B test`、前端 `npm test` 与 `npm run build`（vue-tsc 类型检查 + 生产构建）。本地可用 `cd backend && ./mvnw -B test`、`cd client && npm test` 一键复现，当前全部通过。

### 3.2 测试类覆盖矩阵

| 测试类 | 层次 | 覆盖内容 |
|---|---|---|
| RecursiveSplitterTest | 后端单元 | 递归切分：空文本、短文本、超长片段多级分隔符续切、重叠切分 |
| ChunkerTest | 后端单元 | 法规条款切分、空边界、条款引用（clause_ref）保留 |
| HybridRetrieverTest | 后端单元 | RRF 融合得分随排名递减、双路命中叠加、null 排名归零；hash 向量维度契约 |
| JwtUtilTest | 后端单元 | 签发↔解析往返、篡改失效、过期失效、空密钥 fail-fast |
| JwtAuthenticationFilterTest | 后端单元 | 有效 token、禁用用户拦截、无 token 放行、鉴权链路 |
| SessionControllerTest | 后端单元 | 会话越权（读 / 改名 / 删除）、匿名 401、会话不存在、owner 正常路径 |
| KnowledgeServiceTest | 后端单元 | 上传文件名净化、路径穿越、非法字符、超长名、落盘目录边界 |
| request.test.ts（Vitest） | 前端单元 | 请求拦截器：token 注入、业务错误码、401 登出、auth 端点例外 |

### 3.3 新增回归用例（完结复查后补齐）

- **越权（IDOR）回归**：SessionControllerTest 覆盖「非 owner 读 / 改名 / 删除他人会话返回 403」「匿名列出会话返回 401」，并断言越权时 Mapper 不被调用，防止水平越权。
- **维度回归**：HybridRetrieverTest 新增 `hashEmbeddingDimensionMatchesPgvectorColumn`，同时断言 `dimension()` 声明值与实际 `embed()` 输出长度均为 1024，与 `vector(1024)` 一致，避免写入向量列时才发现维度不匹配。
- **密钥回归**：JwtUtilTest 新增 `blankSecretFailsFast`，断言未配置 `JWT_SECRET` 时在启动校验阶段即抛 `IllegalStateException`，而非登录时才报弱密钥错误。
- **上传净化回归**：KnowledgeServiceTest 覆盖 Unix / Windows 双风格 `../` 路径穿越、目录前缀、点段名、null / 空名、中文与非法字符、超长名截断，以及「净化后再落盘」的端到端目录逃逸校验。

### 3.4 检索质量评估与 Prompt 迭代测试

- **检索质量评估**：以固定问题集对比不同 `rag_score_threshold`、`rag_top_k_recall` / `rag_top_n_final`（topK）、`chunk_size` / `chunk_overlap` 组合下的命中率与答案准确率，选定默认参数（阈值 0.3、召回 20、保留 5、切片 500/80）。
- **Prompt 迭代测试**：系统提示词经多轮迭代（引用标注由「每句话标注」优化为「仅在首次引用处标注一次」，并加入「资料不足就明说」的反幻觉约束），通过人工评测对比生成质量；核心功能保留完整 Prompt 链快照（`docs/AI-Prompt历史快照.md`）。
- **端到端分阶段验收**：按「文档导入 → 检索问答 → 流式 SSE → 思考可视化 → 管理端 → 复现与材料」分阶段验收，从学生视角（提问 / 溯源 / 会话 / 个人中心）与管理员视角（语料 / 配置 / 大屏 / 用户 / 公告）逐项走查，并修复流式自动停止、删除残留、多标签串号等边界问题。

### 3.5 数据层规范化

全库 **9 张表、64 个字段**逐一补齐中文注释（表注释 + 字段注释），并按查询模式梳理出 **22 个索引**（含主键 / 唯一 / FULLTEXT ngram / 普通二级索引）：例如 `idx_user_update(user_id, update_time)` 服务会话列表倒序、`idx_doc_chunk(document_id, chunk_index)` 服务切片预览与级联删除、`idx_top_create(top DESC, create_time ASC)` 消除公告排序 filesort；同时刻意不为低基数列与 MEDIUMTEXT 分组列建立冗余索引。变更语句与逐条依据见 `sql/migrate_indexes_comments.sql`，使结构自解释、可审计。

## 四、关键技术

| 层次 | 关键技术 |
|---|---|
| 前端 | Vue 3 + TypeScript + Vite + Element Plus + Pinia + Vue Router + ECharts + markdown-it（Axios + fetch 流读取） |
| 后端 | Java 17 + Spring Boot 4.1 + MyBatis-Plus + Spring Security + JWT（SseEmitter 流式） |
| 大模型 | 生成 DeepSeek `deepseek-chat`（SSE 流式）；向量化 DashScope `qwen3.7-text-embedding-flash`（1024 维，可切免密钥 hash，同为 1024 维）；重排 `qwen3.7-text-rerank` |
| 向量库 | pgvector（PostgreSQL 16，`vector(1024)` 余弦相似度，Docker 持久化，含内存回退层） |
| 数据库 | MySQL 8（9 张表元数据 + **FULLTEXT ngram 全文检索**，64 字段注释 + 22 索引规范化）；**Redis 7 容器与依赖保留、当前业务逻辑未启用缓存** |
| 检索链路 | Query 改写 → 混合检索（pgvector 向量 + MySQL 全文关键词）→ **RRF 融合** → Rerank 精排 → 相关性阈值过滤 → Prompt 组装 → 流式生成 → [来源N] 溯源标注 → 会话落库 |
| 文档解析 | PDFBox（pdf）、Apache POI（doc / docx）、多编码 txt / md；按法规条款边界切分并保留 clause_ref |
| 安全 | JWT HS256（实时查库鉴权）、BCrypt 密码哈希、限流过滤器、**IDOR 会话归属校验**、上传文件名净化与落盘边界、source_url 协议白名单、全局异常响应脱敏、密钥环境变量化 + 空密钥 fail-fast |
| 部署 | Docker + Docker Compose 三容器（MySQL 8 / Redis 7 预留 / pgvector），前后端分离（8081 / 5173），`.env` 变量注入 |
| 测试与 CI | JUnit 5 + Mockito（34 例）、Vitest（7 例）、GitHub Actions（push / PR 自动跑后端测试、前端测试、vue-tsc 类型检查与生产构建） |

**RAG 流水线**：文档上传 → 文本提取 → 按条款递归切分 → 向量化入库 →（提问时）Query 改写 → 混合检索 → RRF 融合 → Rerank 精排 → 阈值过滤 → Prompt 组装 → 流式生成 → 溯源标注 → 会话落库。

## 七、若项目是在其他项目基础上优化

本项目为**从零开发的原创项目**，**未基于任何其他项目**进行二次开发；后端、前端、RAG 链路、数据库脚本与参赛材料均从空仓库逐步构建，99 次细粒度 git 提交完整记录了从脚手架到全功能的演进过程。

在**自身迭代**中，完结复查后完成了以下优化，均已在代码与回归用例中落地：

1. **越权 IDOR 修复**：会话读 / 改名 / 删除与流式问答补齐 owner 归属校验，越权返回 403，并新增 SessionControllerTest 回归。
2. **向量维度统一**：hash 与 dashscope 两种 embedding provider 统一输出 **1024 维**，与 `vector(1024)` 严格一致，新增 HybridRetrieverTest 维度契约回归。
3. **上传路径穿越修复**：文件名净化覆盖 Unix / Windows 双风格分隔符、点段、超长名，落盘限定在 `uploads/original` 内，新增 KnowledgeServiceTest 净化与落盘边界回归。
4. **事务与错误契约**：语料删除改为「切片 + 向量 + 物理文件」级联且分步容错；前后端统一 `Result` 错误码与业务异常契约，异常响应统一脱敏。
5. **SSE 边界处理**：修正换行分片、`complete()` 与落库顺序、前端 `done` 事件提前停止，解决生成结束后仍转圈、断连与空回答等边界；SSE 场景下全局异常处理按 `text/event-stream` 写出而非返回 JSON。
6. **前端统一错误链**：axios 拦截器统一 token 注入、业务错误码、401 登出与 auth 端点例外，形成一致的错误提示与重试体验。
7. **单层输入框**：问答输入收敛为单层输入框，简化交互、避免多标签串号（配合 sessionStorage 隔离）。
8. **AI 气泡阅读宽度**：调整回答气泡最大宽度与 markdown 排版，提升长答案可读性。
9. **分类「其他」**：在 6 大类之外补充「其他」兜底分类（共 7 类），保证未归类制度文件也能入库与统计。
10. **全库索引与注释规范化**：9 张表 64 个字段补齐中文注释、梳理 22 个索引并逐条记录建索引依据（`sql/migrate_indexes_comments.sql`）。
11. **80 个源码文件三层中文注释**：对后端与前端共 80 个源码文件补齐全文件级「覆盖模块 / 回归目标」、类级、方法级「被测行为 / 前置 / 期望 / 回归」三层中文注释，提升可维护性与评审可读性。

以上优化均为项目自身版本演进，不涉及对第三方项目的改造；配套 20 页 Word 技术文档与 5–8 分钟演示视频（含 ≥2 分钟 AI 协同过程复现）对关键实现与复现步骤作了完整记录。
