# 学事通（CampusPedia）作品介绍文档

> 面向高校学生的校园事务智能问答助手 · 基于 RAG（检索增强生成）技术

---

## 一、项目详情及使用方式

### 1.1 项目详情

**学事通（CampusPedia）** 是一款面向高校学生的校园事务智能问答系统。它将学校公开的制度文档（学籍管理、奖惩处分、奖助学金、宿舍管理、素质拓展学分、就业、医保等）导入后，基于「**混合检索 + 重排序 + 大模型**」技术，为学生提供**流式问答、答案溯源引用**的一站式咨询体验，解决"翻多套系统、反复问群、问客服慢"的低效信息获取问题。

与传统关键词搜索或通用大模型相比，学事通的核心理念是：**只依据学校真实资料回答，杜绝"一本正经胡说八道"**，且每条答案都能溯源到具体文件条款。

系统围绕 **6 大校园事务主题** 建立语料分类：学籍与教学管理、学生管理、学生奖助、素质拓展、学生就业、医疗保障。

### 1.2 使用方式

**部署（管理员侧）**

1. 环境要求：Docker、JDK 17、Node.js；
2. 一键启动三容器（MySQL 8 / Redis 7 / pgvector）：`docker compose up -d`；
3. 配置 API Key 环境变量（DeepSeek、DashScope、JWT 密钥等），启动后端（Spring Boot，端口 8081）与前端（Vue3，端口 5173）。

**使用（学生侧）**

1. 用「学号 + 密码」注册 / 登录；
2. 在聊天框输入自然语言问题（如"转专业需要什么条件？"），系统**流式作答**并标注来源 [来源N]；
3. 点击来源编号，查看命中的具体文件条款；
4. 左侧查看 / 重命名 / 删除历史会话（刷新不丢）；
5. 个人中心可修改姓名、专业、班级，更换头像、修改密码。

**管理（管理员侧）**

- **语料管理**：上传 md / txt / pdf / doc / docx，一键向量化，预览切片，删除；
- **参数配置**：在线热更新切片大小、召回数、重排阈值、系统提示词等 RAG 参数；
- **数据大屏**：问答量、文档类型分布、热门问题可视化；
- **用户管理**：角色 / 状态管理、资料编辑；
- **公告管理**：发布系统公告。

## 二、项目亮点

1. **混合检索 + 重排，答案精准可溯源**：pgvector 向量检索 + MySQL 全文（ngram）关键词检索 + RRF 融合 + 大模型重排 + 阈值过滤，回答标注 [来源N]，点击可查原文条款；
2. **多轮对话 Query 改写**：大模型对追问进行改写，融合历史语境，解决"它""那个""能转几次"等指代与省略问题；
3. **流式输出体验**：SSE（Server-Sent Events）打字机效果，边生成边展示，可随时停止；
4. **三级权限 + 实时鉴权**：游客 / 普通用户 / 管理员分级；鉴权实时查库，禁用用户即时生效；
5. **完整管理后台**：数据大屏可视化、RAG 参数在线调优、语料全生命周期管理；
6. **安全加固**：密钥环境变量化、JWT 无状态鉴权、接口限流、BCrypt 密码加密、越权漏洞修复；
7. **健壮可降级**：embedding 支持 hash 降级，rerank / 检索失败自动兜底，缺密钥也能离线运行。

## 三、AI 测试技术落地使用情况概述

项目采用「**自动化单测 + 分阶段人工验收**」结合的测试体系，重点保障 AI 检索链路与安全逻辑的正确性。

**1. 单元测试（JUnit 5 + Mockito，共 16 例全部通过）**

| 测试类 | 覆盖内容 |
|---|---|
| RecursiveSplitterTest（4 例）| 文本递归切分的空文本、短文本、超长切片、重叠切分 |
| JwtUtilTest（3 例）| JWT 签发↔解析往返、篡改失效、过期失效 |
| HybridRetrieverTest（3 例）| RRF 融合得分：排名越靠前得分越高、两路命中加分、空排名归零 |
| JwtAuthenticationFilterTest（3 例）| 鉴权过滤器：有效 token、禁用用户拦截、无 token 放行 |
| ChunkerTest（3 例）| 法规条款切分、空边界、条款引用保留 |

运行 `mvn test` 即可一键复现，全部通过（BUILD SUCCESS）。

**2. 检索质量评估**：通过调整重排阈值（rag_score_threshold）、召回数（topK）、切片大小等参数，对比不同配置下的问答准确率，选定最优参数组合。

**3. Prompt 迭代测试**：系统提示词经过多轮迭代（如引用标注从"每句话标注"优化为"仅首次引用标注一次"），通过人工评测对比生成质量。

**4. 端到端分阶段验收**：从用户视角（提问 / 溯源 / 会话 / 个人中心）与管理员视角（语料 / 配置 / 大屏 / 用户 / 公告）逐项验收，修复了大量边界问题（如流式自动停止、删除不彻底、越权访问、多标签串号等）。

## 四、关键技术

| 层次 | 技术 |
|---|---|
| 前端 | Vue 3 + TypeScript + Vite + Element Plus + Pinia + ECharts + markdown-it |
| 后端 | Java 17 + Spring Boot 4.1 + MyBatis-Plus + Spring Security + JWT |
| 大模型 | DeepSeek deepseek-chat（生成）、DashScope qwen3.7-text-embedding-flash（1024 维向量）、qwen3.7-text-rerank（重排）|
| 向量库 | pgvector（pg16，余弦相似度）|
| 数据库 | MySQL 8（元数据 + FULLTEXT ngram 全文检索）、Redis 7（缓存）|
| 检索链路 | 混合检索（向量 + 关键词）+ RRF 融合 + 重排 + 阈值过滤 |
| 文档解析 | PDFBox（pdf）、Apache POI（doc / docx）、多编码 txt / md |
| 安全 | JWT（HS256）、Spring Security、BCrypt、限流过滤器 |
| 部署 | Docker + Docker Compose 三容器 |

**RAG 流水线**：文档上传 → 文本提取 → 递归切分 → 向量化入库 →（提问时）Query 改写 → 混合检索 → Rerank 精排 → 阈值过滤 → Prompt 组装 → 流式生成 → 溯源标注 → 会话落库。
